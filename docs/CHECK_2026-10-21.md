## 3. Health

**Injury feed freshness at the last board build — honored, with one caveat.**
- Feed came from a live ESPN pull inside the board run: cache `saved_at`
  2026-10-19T22:45:02.9Z (ATL) / 22:45:03.2Z (GS); board artifact written 22:48:29Z. Staleness at
  build = **3m26s** (22:45:02.919Z -> 22:48:29.019Z).
- Ordering is as intended: the fetch happens in `_collect_player_logs`
  (`run_forecast_pipeline.py:236-268`), invoked at the `stage=player_logs` step, i.e. after player
  prop capture and before `stage=board` (line ~474). No board path reads injuries before that.
- Caveat: nothing forces the pull. Default `refresh_injuries=False` serves `JsonCache` with
  `injuries_cache_ttl_minutes=10` (`config.py:126/213`); the fail-closed `--refresh-injuries`
  path exists only in `run_linux_task.sh` mode `refresh` (line 71-72), whose unit
  `sports-wnba-forecast-refresh.service` (17:00 ET) and `sports-wnba-forecast@afternoon.timer`
  are **disabled**. Today's daily 18:45 cadence always exceeds the 10-minute TTL, so the pull
  happens — but that is a side effect of scheduling, not a guarantee.
- Failure mode worth naming: the default branch wraps the fetch in `except Exception: injuries=[]`
  with no log line, and `health_report()` (`board.py:587-649`) has no injury check. An ESPN outage
  therefore produces `health=ok` with zero injury context; the only trace is
  `provenance.injuries_by_team` being empty. Game 2 shows `{ATL: 2, GS: 1}`.

**Traceability — present in schema, unexercised in practice.**
- Board `injury_trace = {screen_date: 2026-10-19, events: [], event_count: 0}`;
  `outputs/ledger/injury_events.jsonl` does not exist, i.e. the trace log has never received a row
  (pipeline logged `[pipeline] injury-trace events=0 appended=0`).
- Cause is structural, not a crash: `rotation_minute_detail()` builds `out_entries` from
  `player_statuses ∩ roster_minutes`, and `roster_minutes` is built from `logs_by_player`, which
  contains only prop-line subjects. On 2026-10-19 the three OUT players (Matilde Villa, ATL,
  coach's decision; Brionna Jones, ATL, leg/season; Iliana Rupert, GS, not injury related) carried
  no prop lines, so no vacated minutes were computed and no events were emitted.
- Consequence in the artifact: `injury_debit_pts_home = injury_debit_pts_away = 0.0` on the TOTAL
  and SPREAD rows, and `total_pre_debit == total_post_debit`. Defensible for these three (all
  long-known absences already priced into team form: Jones since 2026-08-13, Rupert out for the
  season), but it means the Finals have produced **zero** traceability rows to inspect.
- Documentation mismatch: the `_rotation_minute_bumps` docstring says the roster "is sourced from
  game logs (not prop lines) so an OUT star whose line was pulled still vacates minutes", while the
  implementation can only see players who currently have lines. A star whose line is pulled is
  exactly the case that cannot produce an event.

## 4. Verdict

- **Performance evaluation — watch.** One graded Finals game (45 priced units) plus one uncovered
  game. Nothing here distinguishes the post-multiplier regime from the -8.05% playoff baseline.
  Would change the answer: 3+ graded Finals games (~120-150 priced rows) for a directional read;
  ~400 priced rows for +/-5pp ROI resolution. No model or multiplier change is justified by n=45,
  and per the Nov 1 schedule nothing is retuned now regardless.
- **Injury feed freshness/ordering — working.** Live pull 3m26s before the artifact, correct stage
  order, TTL expiry guaranteed by the daily cadence. Watch item only if a second same-day run is
  ever scheduled inside the 10-minute TTL.
- **Injury feed failure detection — fix candidate.** Silent `injuries=[]` on fetch error plus no
  injury check in `health_report()` means a dead feed is indistinguishable from a healthy slate at
  the `health=ok` line. Evidence bar: one run with a forced/observed fetch failure while games are
  scheduled should surface a non-`ok` reason; today it would not.
- **Injury traceability — fix candidate.** The Finals produced 0 events and the JSONL log has never
  been written, because the redistributable-out roster is limited to current prop subjects. Evidence
  bar: a game where a rotation player with a prop line is ruled out must yield >=1 event, an
  `outputs/ledger/injury_events.jsonl` row, and one adjudication row under `outputs/grades/injury_trace/`.
  Until then the trace path is schema-only. (Read-only review: no code change made.)
- **Slate coverage — fix candidate.** Game 1 is a permanent hole in the Finals sample: the slot name
  was the instance name, and the fallback timer fires after afternoon tips. Validation now fails
  fast instead of arguing with argparse, but the 2026-10-24 matinee still relies on a manual arm.
  Evidence bar: one successful `@afternoon` one-off on a pre-18:45 ET tip producing a graded board.
- **Debits.** No retune recommendation; the Nov 1 lookback owns that decision.
